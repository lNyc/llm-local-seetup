# Observability

The stack ships with a full telemetry pipeline out of the box — inference traces, GPU metrics, and logs all flow into ClickHouse and are surfaced in the OpenLIT dashboard. No external services required.

---

## Pipeline Overview

```
KoboldCPP (via LiteLLM OTEL callback)
        │
        │  traces (HTTP/4318)
        ▼
GPU Collector ──► OTEL Collector ──► ClickHouse ──► OpenLIT
  (GPU metrics)    (4317 gRPC /        (port 9000       (port 3000)
                    4318 HTTP)          TCP native)
```

**LiteLLM** emits OpenTelemetry traces for every inference request via its built-in `otel` callback.

**otel-gpu-collector** polls `nvidia-smi` and emits GPU hardware metrics as OTEL metrics.

**OTEL Collector** receives all signals, applies transforms, batches, and exports to ClickHouse.

**ClickHouse** stores traces, metrics, and logs in columnar format — well-suited for the aggregation queries OpenLIT runs.

**OpenLIT** reads from ClickHouse and provides the dashboard UI.

---

## Accessing the Dashboard

Open WebUI: **http://localhost:3000**

Default credentials are set on first launch. `NEXTAUTH_SECRET` in `.env` is used to sign sessions — keep it a strong random string.

## What Gets Collected

### Inference Traces

Every request that passes through LiteLLM generates a trace with:

- Model name
- Request / response token counts
- Latency (time to first token, total generation time)
- Operation type (`chat`, `completion`)

Traces are tagged with `gen_ai.operation.name`. The OTEL Collector config normalises `acompletion` → `chat` so async calls appear consistently in the dashboard.

### GPU Metrics

Collected by `otel-gpu-collector` and renamed by the OTEL Collector transform pipeline:

| Metric | Description |
|---|---|
| `gpu.utilization` | Core utilisation % |
| `gpu.temperature` | Die temperature (°C) |
| `gpu.memory.used` | VRAM usage |
| `gpu.power.draw` | Current power draw (W) |
| `gpu.fan_speed` | Fan speed % |
| `gpu.clock.graphics` | Core clock (MHz) |
| `gpu.clock.memory` | Memory clock (MHz) |
| `gpu.power.limit` | Power limit (W) |

These are tagged with `GPU_APPLICATION_NAME` and `GPU_ENVIRONMENT` from `.env`, which lets you filter by deployment in the dashboard.

### Logs

All OTEL logs received by the collector are forwarded to ClickHouse. LiteLLM and KoboldCPP logs are captured at the Docker level — structured logs emitted over OTEL are stored separately from container stdout.

## OTEL Collector Configuration

The collector config lives at:

```
Infrastructure/middleware/open_telemetry/config.yaml
```

Key sections:

**Receivers** — listens on both gRPC (4317) and HTTP (4318) for any OTLP-compatible source.

**Processors** — two transform stages:
- `transform/traces`: normalises operation names for consistent dashboard grouping
- `transform/gpu_metrics`: renames raw `hw.gpu.*` metric names to the shorter `gpu.*` names OpenLIT expects

**Exporters** — single ClickHouse exporter using the native TCP protocol on port 9000, with LZ4 compression and async inserts enabled for throughput.

**Pipelines** — traces, metrics, and logs each have their own pipeline. GPU metrics go through `transform/gpu_metrics`; traces go through `transform/traces`; logs pass through with only batching applied.

## ClickHouse

ClickHouse is the storage backend. It's not intended to be accessed directly during normal operation — OpenLIT queries it internally.

If you need to inspect data directly:

```bash
docker exec -it clickhouse clickhouse-client \
  --user $CLICKHOUSE_USER \
  --password $CLICKHOUSE_PASSWORD
```

Useful queries:

```sql
-- Recent inference traces
SELECT timestamp, SpanName, Duration FROM otel_traces ORDER BY timestamp DESC LIMIT 20;

-- GPU utilisation over time
SELECT toStartOfMinute(TimeUnix) AS minute, avg(Value)
FROM otel_metrics_gauge
WHERE MetricName = 'gpu.utilization'
GROUP BY minute ORDER BY minute DESC LIMIT 30;
```

Table names may vary depending on the OpenTelemetry Collector contrib ClickHouse exporter version. Run `SHOW TABLES` to see what's available.

## Disabling Telemetry

OpenLIT's own anonymous usage telemetry is disabled in the Compose config:

```yaml
TELEMETRY_ENABLED: "false"
```

If you want to disable inference tracing entirely, remove the `callbacks` line from `litellm-config.yml`:

```yaml
litellm_settings:
  callbacks: ["otel"]   # remove this line
```

GPU metrics can be stopped by removing the `otel-gpu-collector` service from `open_telemetry.yml`.
